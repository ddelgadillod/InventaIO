# InventAI/o v2.0.0 · Release 2: Predictivo y Conversacional v1

Cierra el Release 2: Sprints 4 a 6, del 14 de septiembre al 31 de octubre de 2026, con 24 historias y 145 puntos de historia en Jira. Corre en local con Docker Compose; el despliegue en la nube es del Release 3.

## Qué trae

**Datos**
- Bodega revalidada y adaptada al dataset real de ventas POS, con un ETL que consolida los reportes de varios archivos.
- Análisis exploratorio y de calidad de datos, e ingeniería de variables.

**Pronóstico de demanda**
- MLflow para los experimentos, modelo base, pronóstico con festivos colombianos y selección del mejor modelo.
- Motor por segmento: LightGBM cuantílico con calibración conformal en la rama de demanda intermitente, y media móvil con cuantil empírico en las ramas de demanda suave.
- `ml_service` con su imagen y el endpoint de predicción; reentrenamiento manual y documentado.

**Recomendaciones y alertas**
- Compras a proveedor con punto de pedido, nivel objetivo y calendario fijo; traslados entre sucursales; y sus endpoints en `ml_service`.
- Alertas con IA: riesgo de desabastecimiento y sobrestock previstos.

**Core API y aplicación web**
- Core API auditado y homologado con la bodega real.
- Vistas de Predicciones y de Recomendaciones de compra y traslado.

**Vera, el asistente conversacional**
- Agente autoalojado con Ollama y Qwen3 8B, sin APIs externas.
- Glosario del negocio con búsqueda BM25 y conjunto de referencia para evaluarlo.
- Diez herramientas de solo lectura sobre el Core API, que usan el token de quien pregunta y ven lo mismo que esa persona.
- Prompts por rol, verificación de la respuesta antes de mostrarla y flujo conversacional.
- API de chat en el Core API con streaming por SSE, detrás de Nginx.
- Ventana de chat en todas las pantallas, con tablas, sugerencias, «Detener» y «Copiar».

**CI/CD**
- GitHub Actions con ruff, pruebas con cobertura mínima, `pip-audit` y `npm audit`; imágenes sin root, escaneadas con Trivy, verificadas con el compose y publicadas en GHCR.

## Cambios frente al plan

| Planeado | Entregado |
| --- | --- |
| LightGBM para todos los productos | LightGBM solo en la rama intermitente; en las ramas suaves, la media móvil con cuantil empírico |
| Motor EOQ para las compras | Punto de pedido, nivel objetivo y calendario fijo |
| Agente y chat en el Release 3 | Adelantados a este release |
| Llama como modelo del agente | Qwen3 8B, que superó a Llama en el spike del agente |
| RAG con NL→SQL | Herramientas de solo lectura que heredan los permisos del Core API |
| PWA desde el Release 1 | Pasa al Release 4; hoy la aplicación se abre en el navegador |

## Limitaciones conocidas

- **Solo local.** El primer despliegue en AWS, en staging, es del Release 3.
- **No apta para internet.** La configuración tiene secretos con valor por defecto, CORS abierto y usuarios de demostración. Se corrige con el hardening del Release 3, antes del primer despliegue.
- **Datos hasta el 31 de diciembre de 2025.** El motor se reevalúa con las ventas de 2026 en el Release 3.
- **Vera necesita Ollama con GPU.** Con la GPU local, una respuesta puede tardar uno o dos minutos. Responde sobre los datos, no sobre cómo usar la aplicación (llega en el Release 4), y no guarda el historial de conversaciones (Release 5).

## Seguridad

- `pip-audit` sin vulnerabilidades conocidas y sin excepciones en los servicios de Python: python-jose se reemplazó por PyJWT.
- Trivy sin vulnerabilidades CRITICAL con corrección disponible en las cuatro imágenes.
