# InventAI/o v2.1.0 · Versión intermedia del Release 3: lista para exponer

Primer avance del Release 3, en el Sprint 7, que empezó el 2 de noviembre de 2026. Trae la seguridad mínima para exponer la aplicación a internet, las dependencias al día y ajustes para el celular. **No es el Release 3**: el Release 3 es la primera versión en la nube, con el tag `v3.0.0`. Esta versión sigue corriendo en local, y con ella se prepara el despliegue en AWS.

## Qué trae

**Seguridad para exponer la aplicación**
- Secretos obligatorios: fuera de desarrollo, el Core API y el ML Service no arrancan con las claves del repositorio ni con una clave JWT de menos de 32 bytes. El error nombra la variable que falta, pero no muestra los valores.
- CORS cerrado por defecto, porque el navegador llega por el mismo origen. El ML Service, que es interno, no tiene CORS.
- Límite de intentos fallidos de login: 5 por correo e IP y 20 por IP en 15 minutos, con respuesta 429. Los contadores van en Redis, y en memoria si Redis no responde.
- `docker-compose.prod.yml`: imágenes de GHCR por tag, solo la web publica un puerto, sin pgAdmin, y los secretos salen de un `.env.prod` que no se versiona.
- Usuarios de la nube con claves aleatorias que se muestran una sola vez.
- Cabeceras de seguridad en Nginx con una política de contenido completa: todo sale del mismo origen.

**Aplicación web**
- En el celular, Inventario muestra una tarjeta por producto, con el stock y su estado a la vista.
- Las fuentes vienen con la aplicación, sin Google Fonts.
- La barra superior muestra la página y la versión. El login muestra la versión real, que antes decía «v1.0» fija.

**Una sola versión del producto**
- El archivo `VERSION` es la fuente, `scripts/version.py` la escribe en la interfaz, los tres servicios, el OpenAPI y el README, y el CI falla si alguno no coincide.
- El ML Service y el agente, que tenían versiones propias (1.3.0 y 0.1.0), pasan a la del producto.
- `/api/health` del Core API y del ML Service informan la versión.

**Dependencias**
- Al día las acciones de GitHub, las herramientas de desarrollo del frontend y casi todas las librerías de Python: FastAPI 0.162, SQLAlchemy 2.1, uvicorn 0.54, redis 8, pandas 3.1, pyarrow 26 y ruff 0.17.
- Quedan con cota, cada una con su motivo en `.github/dependabot.yml`:
  - numpy 2.4 y scipy 1.17, porque sus versiones nuevas exigen Python 3.12;
  - bcrypt 4, porque la 5 rompe el login con passlib;
  - React 18, react-router 7, recharts 2 y lucide-react 0.x, cuyos saltos mayores se migran después del staging.

## Al actualizar desde v2.0.0

- **`ENTORNO`:** sin esta variable se asume producción. El compose de desarrollo ya la declara. Quien corra el Core API o el ML Service fuera de Docker debe agregar `ENTORNO=desarrollo` a su `.env`.
- **Las imágenes necesitan secretos propios para arrancar:** `JWT_SECRET_KEY` y `POSTGRES_PASSWORD`. La plantilla está en `.env.prod.example`.
- **La URL de la base declara el driver psycopg2.** SQLAlchemy 2.1 usa psycopg 3 por defecto.
- **En el stack local hay que reconstruir las imágenes,** porque cambian las dependencias: `docker compose --profile web build`.

## Limitaciones conocidas

- **Solo local.** El primer despliegue en AWS, en staging, es la `v3.0.0`.
- **Datos hasta el 31 de diciembre de 2025.** La reevaluación del pronóstico con las ventas de 2026 sigue pendiente.
- **Vera sigue con Ollama local.** El modelo en la nube llega con el staging.
- **Recomendaciones en el celular:** la tabla de líneas de compra se desliza dentro de su caja, y en 360 px el stock queda fuera de la pantalla. Se revisa con las pruebas con usuarios.
- **Pendientes de la revisión de seguridad:** la lista negra de refresh tokens vive en memoria, y el mensaje de cuenta desactivada permite saber si un correo tiene cuenta.
